### Fixed: saving UI settings without the Standard template no longer resets its layout

A `PUT /api/v1/ui-settings` whose `layoutTemplates` left out the built-in Standard template was
accepted and re-created Standard with an empty layout ([GH#521]). Every class and configuration item
using Standard lost its tabs, hidden fields and read-only fields at once, with no warning. Standard is
now carried over from the version being replaced, with its layout, name and description, the same way
restoring an older version or importing a configuration file keeps templates still in use. A client
can keep sending only the templates it edits. A class layout that names Standard and sends tabs or
fields still edits Standard, as before.

**Upgrade:** no schema change. A script that sent empty settings (`"settings": {}`) to go back to the
built-in UI settings now keeps Standard's layout. To clear Standard as well, send it with an empty
layout: `"layoutTemplates": [{"key": "standard", "name": "Standard", "layout": {}}]`. If Standard was
reset by this defect, restore it from an earlier version in the UI settings history.

[GH#521]: https://github.com/Shadoukita/ShadouCMDB/issues/521
