### Security: audit export over TLS, and audit and log files no longer readable by every user

`AUDIT_EXPORT` could only send audit events to a remote SIEM unencrypted (`udp://`, `tcp://`), so
anyone on the network path could read the user names, client addresses and change contents they
carry, or alter and drop them ([GH#443]). The new `tls://host:port` sink sends syslog over TLS
(RFC 5425, octet counting): the collector's certificate chain and host name are always verified,
against the Mozilla root set, the operating system's trust store and, optionally, the PEM file in
the new `AUDIT_EXPORT_TLS_CA_FILE`. A failed connection or handshake is retried on the next poll,
as with `tcp://`. The server now warns at startup when `udp://` or `tcp://` points at a host other
than this one.

On Linux and other Unix systems, a new `file:` audit export file and a new `--log-file` are
created with mode 0640 (owner read and write, group read), whatever the process umask; before,
they were usually 0644. Files that already exist keep their mode.

**Upgrade:** to encrypt an existing remote export, change `AUDIT_EXPORT=tcp://siem:6514` to
`tls://siem:6514` and, for a private CA, set `AUDIT_EXPORT_TLS_CA_FILE`. Check the mode of
existing audit and log files (`chmod 640`). No API or schema change.
