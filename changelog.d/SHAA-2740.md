### Fixed: Delegation windows shorter than a microsecond return the documented validation error

`POST /api/v1/me/approval-delegations` and `POST /api/v1/admin/approval-delegations` checked
`startsAt` and `endsAt` at nanosecond precision, but the database stores microseconds. A window
whose ends differed by less than a microsecond passed the check and was then refused by a
database constraint, so the `400` response named an internal table and constraint on field
`(root)` ([GH#822]). Both timestamps are now truncated to microseconds when the request is read,
so such a window gets `400 VALIDATION_ERROR` with `endsAt` / `out_of_range`, like any window
that does not end after it starts. The 90-day limit is checked on the stored values in the same
way.

**Upgrade:** nothing to do; no configuration or schema change.
