### Added: Adopting existing CIs into a workflow from the web UI

- **Administration › Workflows › Settings › Adopt existing CIs.** For a workflow that drives a state
  field, a **Preview bootstrap** dry run shows how many covered CIs would get an instance, per state,
  how many already run the workflow, and which state field values no state maps (those CIs are skipped
  and keep a locked state field). **Start instances** then runs the bootstrap after a confirmation with
  those numbers. The *CIs without an instance* warning shown after activating such a workflow links to it.
- **CI form and CI page.** A field that an active workflow drives (its state field) is shown read-only,
  marked *Set by a workflow*, instead of failing on save. It changes through a transition on the CI's
  Workflows tab.
