### Security: the audit log no longer lists Application field values to readers who may not view Application

The upgrade that archived the Application field "criticality" (migration 0036) records one audit
entry on the field, listing the values that did not map onto the core Criticality
(`notMappedValues`). `GET /api/v1/audit-log` showed that list to every audit reader, including
readers whose permission profile does not let them view Application, and for a text field those
are free-text values stored in CIs ([GH#392]). The list is now shown only to a reader who may view
the field's type and every type below it; everyone else still sees the entry and its counts
(`notMapped`, `criticalitySet`, ...). The check runs when the log is read, so entries written
before this release are covered.

**Upgrade:** nothing to do.
