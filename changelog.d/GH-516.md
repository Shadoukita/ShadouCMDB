### Fixed: saved import mappings no longer accept the business service membership type

A saved import mapping could still target the built-in business service membership type
(`POST /import-mappings` answered `201`), and a mapping saved before the upgrade was suggested with
that column, which `PUT /imports/{id}/mapping` then refused ([GH#516]).

- `POST /import-mappings` and a `PATCH /import-mappings/{id}` that sends a definition refuse such a
  column with `400` and code `system_relationship_type` on `definition.columns[i].target.typeKey`.
- A mapping saved before stays readable. Saved mappings carry a new `problems` list naming the
  column and what to do; the mapping suggestion leaves the column unmapped (`hint`
  `system_relationship_type`), so the suggested mapping is accepted.
- A configuration transfer file carrying such a mapping imports it with that column set to ignore,
  with a warning.

**Upgrade:** open each saved mapping whose `problems` list is not empty, set the business service
column to ignore or remove it, and save. Add members on the business service.
