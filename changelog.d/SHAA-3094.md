### Security: Test sends hold their limit under concurrent requests; the mail test is rate limited

The test send of a workflow action (`POST /api/v1/workflows/{id}/actions/{key}/test`) allows 10 a
minute per user, but concurrent requests could all pass the check, because it counted audit
entries that are written only after the send (GH#899). Each test send now takes a slot in the new
table `cmdb.test_send_slots` (migration 0084) before it goes out, under a per-user lock, so the
limit holds for concurrent requests and across server processes. The mail test
(`POST /api/v1/admin/mail/test`) had no limit and now allows 10 a minute per user as well
(GH#904). Beyond the limit both answer 429 `RATE_LIMITED` with `Retry-After`, and nothing is sent
or audited. A refusal for a missing e-mail address or a paused endpoint does not use up a slot.
