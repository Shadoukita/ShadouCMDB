### Security: purge previews and re-parenting refusals count values only for users who may view them

Since [GH#221] a field change checked against stored values needs the view right on the field's type and every
type below it. Two data-model answers still told a user with the data-model permission how many values assets of
a type they may not view store ([GH#243]): the preview and record of a purge (how many values of a field, or how
many CIs and relationships of a type, are deleted), and the refusal to move a type to a new parent (which fields
of the moved CIs hold values).

For a user without the view right on the type and every type below it, a purge preview and the recorded schema
change now say only that the values or rows are deleted (`impact[].rows` is `null`), and a re-parenting refusal
no longer names the fields. Users with that view right see the counts and field names as before.

[GH#243]: https://github.com/Shadoukita/ShadouCMDB/issues/243
