### Security: `reset-undecryptable` no longer resets everyone when run without the encryption key

Run in a shell that lacked the service's `ENCRYPTION_KEY_FILE`, `shadoucmdb mfa reset-undecryptable
--yes` counted every stored authenticator secret as undecryptable and turned off two-factor sign-in
for every enrolled user ([GH#223]). `shadoucmdb identity-providers reset-undecryptable --yes` did
the same to every identity provider with a stored secret ([GH#239]). Without `ENCRYPTION_KEY_FILE`, both
commands now refuse and change nothing, `--yes` included. When the key is really lost and none is
configured any more, pass the new `--no-key` option to treat every encrypted secret as
undecryptable, as before. `--no-key` together with a configured key is refused as well.

**Upgrade:** scripts or runbooks that run `reset-undecryptable` without `ENCRYPTION_KEY_FILE` on
purpose (the key is lost) must add `--no-key`. Otherwise run the commands with the service's env
file (`--env-file`).
