### Security: tighter checks on list sorting, identity provider tests and logged configuration

Defense-in-depth changes from the security review ([GH#192]); none of them was exploitable on its own:

- The lists of classes, attribute definitions, relationship types and rules, areas, statuses,
  environments, locations, owners, lookup lists and their values now check `sort` against the fields
  each list allows before building the query, in addition to the request validation against the API
  specification. Any other value answers 400 `VALIDATION_ERROR` on `sort`, as before.
- `POST /api/v1/admin/identity-providers/{id}/test` now refuses API tokens (403 `FORBIDDEN`), like
  creating, changing and deleting an identity provider. Run the test from a signed-in session.
- Debug output of the service configuration and of identity provider records no longer contains the
  database passwords (`DATABASE_URL`, `MIGRATION_DATABASE_URL`, `MAINTENANCE_DATABASE_URL`,
  `PGPASSWORD`), OIDC client secrets or LDAP bind passwords.

**Upgrade:** automation that calls the identity provider test endpoint with an API token must call it
from a signed-in session instead. Nothing else to do; no schema change.
