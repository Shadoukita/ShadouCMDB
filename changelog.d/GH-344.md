### Security: importing a configuration file with large former lookup tables no longer blocks other imports

A configuration file from 0.1.0-rc.1 or earlier carries the former statuses, environments,
locations and owners tables, which an import turns into lookup lists. For many owners with similar
names, or a file with many lookup lists, that conversion took time that grew with the square of the
number of rows: a file within the size limits could keep one server thread, one database
connection and the configuration import lock busy for minutes, and the request timeout could not
stop it ([GH#344]). Only users with both `config.export_import` and `datamodel.manage` can import a
configuration file. The conversion now takes time in proportion to the size of the file. The keys
it gives owners and lists (`jane_doe_2`, `status_2`, ...) and the lists it reuses are unchanged. No configuration, API or
schema change.

**Upgrade:** nothing to do.
