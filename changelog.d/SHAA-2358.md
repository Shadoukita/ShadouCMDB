### Added: Clone a CI and print its QR label from the CI page

The CI page has two new actions:

- **Clone** opens the form for a new CI of the same class, filled in with the CI's attribute values
  and criticality. Nothing is saved until you select Create, and the new CI is created like any
  other: it needs the create right on the class, the server validates it, and the audit log records
  it as a new CI. The following are not copied: the ident (generated as usual), the validity period
  (the new CI is valid from now), relationships, history and workflow state. These fields are left
  empty for you to fill in: the class's title field (the CI's name), IP addresses, a Person's Name
  and Email, fields marked as identifying (such as Serial number and Asset tag, see `isIdentifying`)
  and references to CIs you may not view. A field that an active workflow controls on the source CI
  starts at its default value. Other values are copied: review any that belong to a single device
  before you create the CI. The action is shown only to
  users who may create CIs of the class, and not for an archived or abstract class.
- **QR label** shows a QR code that links to the CI, with its name and ident underneath. You can
  print the label or download it as SVG or PNG. Your browser builds the code from the address you
  reached ShadouCMDB under, so the link follows your reverse proxy's host and path. No external
  service is involved, so it works on installations without internet access. Opening the link
  still requires signing in.

No API or database change.
