### Security: A small XLSX file can no longer exhaust the server's memory during import

A user with the import permission could upload a workbook of a few kilobytes that put one very long
text in the shared strings and referred to it from many cells. The import copied that text into
every cell and the server ran out of memory, which stopped the service for all users. Bulk import
now refuses such files with a clear error instead of reading them:

- A cell longer than 10,000 characters, the limit the import settings already state, is refused
  with `cell_too_long` and its row and column, in CSV and XLSX files alike.
- An XLSX row with more than 1 MiB of text is refused with `record_too_long`, the limit a CSV
  record already has.
- An XLSX sheet that holds more text than the upload limit (`IMPORT_MAX_FILE_MB`, 50 MiB by
  default), counting each cell that refers to a shared string, is refused with `text_limit`. The
  error names the configured limit. A workbook can therefore never give the import more text than
  a CSV file of the largest allowed size. ([#446])

Files exported from spreadsheets and inventory tools stay well within these limits. A file that a
previous version accepted with a longer cell is now refused at analysis; shorten the cell or split
the text across columns. ([#403])
