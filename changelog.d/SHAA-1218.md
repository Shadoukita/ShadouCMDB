### Security: A refused sign-in no longer confirms that the password was right

`POST /api/v1/auth/login` used to answer a right password differently from a wrong one when the
sign-in was refused afterwards. A disabled local account got `"This account is disabled"`, and a
directory (LDAP/AD) user whose bind succeeded got the specific refusal, for example "None of your
groups gives access to ShadouCMDB". That let anyone check guessed directory passwords for every
entry the user filter matches, including people with no ShadouCMDB access ([GH#437]).

- **Same answer:** these sign-ins now get the same `401 UNAUTHENTICATED` body as a wrong password,
  `"Invalid username or password"`. The web UI already showed one message for all of them.
- **Reason kept for administrators:** the `login.failure` audit row records why the sign-in was
  refused in `reason`: `account_disabled` for a disabled local account (new), and the directory's
  refusal (`not_authorised`, `account_conflict`, `account_disabled`, ...) as before. The server log
  records it as well. Throttling and account locks are unchanged.

OIDC sign-ins are not affected: after a successful identity provider sign-in, the web UI still gets
the specific `ssoError` reason.

[GH#437]: https://github.com/Shadoukita/ShadouCMDB/issues/437
