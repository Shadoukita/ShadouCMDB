### Added: test send for workflow actions

New endpoint `POST /api/v1/admin/workflow-definitions/{id}/actions/{key}/test` (needs `workflows.manage`
and a session) sends a test of a saved action to the caller only, at once. Nothing goes to the action's
recipients and nothing is queued.

- **E-mail:** the action's message in the caller's language, to the caller's own address. The subject
  starts with `[TEST]` and the first paragraph says who asked for it. With `ciId` the message is about that
  CI. Returns 409 `MAIL_NOT_CONFIGURED` with `MAIL=off`.
- **Webhook:** one signed `ping` to the action's endpoint. It runs the same URL rules and address checks as
  `POST /admin/webhook-endpoints/{id}/ping` but does not need `webhooks.manage`. Returns 409
  `WEBHOOKS_DISABLED` while webhooks are off, and 409 `CONFLICT` when the endpoint is paused or suspended.
- **Inbox:** one notification to the caller. It points to the workflow (new notification entity type
  `workflow_definitions`, `data.test` true).

The result has the same fields for every kind: `ok`, `to`, `statusCode`, `reason`, `message` and
`durationMs`. A refusal by the relay or the receiver is reported in the result, not as an error status. An
action that has not been saved yet returns 404. Each test is audited as `workflow.action_test` on the
workflow, naming the user rather than their address. A caller can send 10 tests a minute; after that the
endpoint returns 429 `RATE_LIMITED`.

Upgrade: migration `0080` adds the audit action and the notification entity type, and `0081` validates the
audit log checks in its own transaction, so audited writes are not held while the log is scanned.
