### Added: Record completeness and CI and relationship count history for the dashboard

Three read-only endpoints give the dashboard its completeness and trend figures:

- `GET /api/v1/configuration-items/completeness` takes the inventory list's filters and returns,
  overall and per class, how many CIs match, how many of them are complete, and how many of the
  expected values they hold. A CI is complete when every counted field of its class (inherited
  fields included) holds a value. By default the counted fields are the required ones and those
  marked as expected; `basis=all` counts every active field.
- `GET /api/v1/configuration-items/{id}/completeness` lists the counted fields of one CI and
  whether each holds a value.
- `GET /api/v1/configuration-items/count-history` and `GET /api/v1/relationships/count-history`
  return the count at the start of a range and, per UTC day or ISO week, the count at its end with
  how many were added and removed. A range covers at most 366 days or 260 weeks.

All four show only CIs in classes the caller may view, as the inventory list does.

Attribute definitions have a new setting, `isExpected`: the field is not required on writes, but a
CI without a value counts as incomplete. Use it for fields operations relies on that are often
unknown when a CI is registered, such as owner, location or serial number. Changes to it are
recorded in the audit log like any other change to a field. Configuration files now carry it
(format version 10). When you import an older file, existing fields keep their setting and new
fields are not expected.

The count history is derived from the timestamps CIs and relationships already carry (created,
deleted, validity period), so it covers the inventory's whole past without a scheduled snapshot
job. A restored CI therefore counts as if it had never been deleted, and a purged CI no longer
appears in past counts.

**Upgrade:** migration `0067` adds `is_expected` to `ci_attribute_definitions`, set to false for
every existing field. Until you mark expected fields, completeness counts only required fields. Run
`shadoucmdb migrate` before starting the new release.
