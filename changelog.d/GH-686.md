### Fixed: turning on subtypes for a workflow answers 403 instead of 404

A manager with `workflows.manage` and the view and edit rights on a workflow's type, but not on a
type below it, could open the workflow but was told it does not exist (`404 NOT_FOUND`) when
setting `includeSubclasses` to `true` through
`PATCH /api/v1/admin/workflow-definitions/{id}` ([GH#686]). The request is now refused with
`403 FORBIDDEN`, as the documented rule for [GH#667] and creating such a workflow already do. The
workflow is unchanged either way. No API schema or database change.

[GH#686]: https://github.com/Shadoukita/ShadouCMDB/issues/686
[GH#667]: https://github.com/Shadoukita/ShadouCMDB/issues/667
