### Security: the 25,000-entry limit of a configuration file covers every section

The limit of 25,000 lookup values per configuration file ([GH#546]) left the other sections out. A
file's `dataModel` section alone could carry about 77,000 areas, classes, attributes, relationship
types and rules, so an applied import could still hold sign-ins and other audited changes for a few
seconds while its audit rows were written ([GH#551]). The 25,000 limit now counts the entries of the
whole file: data-model entries, lookup values (the former `statuses`, `environments`, `locations` and
`owners` sections included), permission profiles, saved import mappings and saved views. A larger file
is refused with 400 `VALIDATION_ERROR` (code `too_big`, reported at the largest section; the message
lists each section's count) before anything is read or changed, for dry runs too.

**Upgrade:** nothing to do for typical installs. If an export of yours carries more than 25,000
entries, split it across several files and import them one after the other, data model first; an
import never deletes, so the entries of earlier files stay in place.
