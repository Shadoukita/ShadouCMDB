### Security: SVG logo and favicon uploads are checked against an allowlist

Uploaded SVG logos and favicons are now parsed as XML and must use only allowlisted drawing elements and
attributes ([GH#192]). This replaces the old search for known-bad markup, which a file could avoid by
spelling the same thing differently. Shapes, text, gradients, patterns, masks, filters, CSS and embedded
PNG, JPEG, GIF or WebP images are accepted, as are Inkscape and Illustrator editor metadata. Refused with
`unsafe_content`: scripts, event handlers, animation, links, `<foreignObject>` and other foreign content,
internal DTD subsets, processing instructions such as `xml-stylesheet`, CSS `@import`, `@font-face` and
escapes, and any reference that leaves the file. The error names the element or attribute that was
refused. Files that are not well-formed XML, or whose root is not `<svg>`, are refused with
`invalid_format`. Assets are still served with a sandboxing Content-Security-Policy and `nosniff`.

**Upgrade:** logos and favicons that are already uploaded keep working and are not re-checked. An SVG
that was accepted before can be refused when it is uploaded again. Re-export it as plain SVG (in
Inkscape, "Plain SVG"; in Illustrator, "SVG" with styling set to "Internal CSS"), or upload a PNG.

[GH#192]: https://github.com/Shadoukita/ShadouCMDB/issues/192
