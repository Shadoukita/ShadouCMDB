### Security: Administrators can no longer commit another user's import, and their access is audited

A bulk import commit writes its CIs with the rights of the user who uploaded the file and names that
user in the audit log. An administrator could start that commit, or change the job's mapping or
file options first, and appear nowhere in the audit log (GH#389).

- **Owner only.** `PUT /imports/{id}/mapping`, `PATCH /imports/{id}/file-options`,
  `POST /imports/{id}/dry-run` and `POST /imports/{id}/commit` now answer `403` with
  `details[0].code = not_owner` when an administrator calls them on another user's import. An
  administrator who wants to import the same file uploads it themselves.
- **Administrators can still view, cancel and delete** any user's import. These actions are now
  audited in the administrator's name:
  - viewing the job (`GET /imports/{id}`) or its problems (`GET /imports/{id}/issues`) writes an
    `import.report_read` event with `view: job` or `view: issues`, at most once per administrator,
    job and view every 15 minutes (the web UI polls the job). Error-report downloads keep writing one
    event each, now with `view: report`;
  - cancelling writes an `update` of `import_jobs` with the status before and after;
  - deleting writes a `delete` of `import_jobs` with the file name, class and owner.
- The import wizard tells an administrator when they are looking at another user's import.
