### Security: anonymous `/readyz` floods no longer queue on the database pool

`GET /readyz` is public and exempt from `HTTP_MAX_CONCURRENT_REQUESTS`, so monitoring never reads a
busy server as down. Each request ran its own database check on the pool signed-in users share, so
a flood of anonymous probes could slow them down ([GH#242]). The readiness result is now reused for
up to 1 s, and concurrent probes wait for the one check in flight: a flood costs about one database
round trip per second. `/readyz` still answers every request with `200` or `503` by the real state,
and a lost database shows within about 1 s plus `DATABASE_CONNECT_TIMEOUT_MS`. `/healthz` and
`/api/v1/version` are unchanged. No configuration change.

[GH#242]: https://github.com/Shadoukita/ShadouCMDB/issues/242
