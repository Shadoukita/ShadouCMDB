### Added: Bulk update of selected CIs

`POST /api/v1/configuration-items/bulk-update` sets the same attribute values (null clears one)
or criticality on 1 to 500 CIs in one request, for the inventory's bulk edit. Each CI is checked
and written exactly as `PATCH /configuration-items/{id}` would write it: the caller needs edit on
the CI's class, values are validated against the CI's class, workflow-controlled fields and
reference rules apply, and every CI that changes gets its own `update` row in the audit log. A CI
the caller may not view is reported as not found, like a missing one.

The answer is always 200 for a well-formed body and lists one result per CI in the request's
order, with the error a single update would have returned for each refused CI. By default the CIs
that pass are saved and the refused ones are left unchanged; with `allOrNothing: true` a single
refusal saves nothing. CIs are locked in a fixed order, so concurrent bulk updates over the same
CIs wait for each other instead of deadlocking. No schema change and nothing to do on upgrade.
