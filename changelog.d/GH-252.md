### Security: the schema change history shows counts only to readers who may view the types counted

Since [GH#243] a purge records how many values or rows it deleted only when the administrator who ran it may view
every type concerned. The history itself (`GET /api/v1/schema-changes` and `GET /api/v1/schema-changes/{id}`)
still returned those counts to every user with the data-model permission, as did the record of a field type
change (how many values were converted) and a template install or reconcile that left a required field nullable
(how many assets have no value) ([GH#252]).

Each schema change now records the types whose data its counts describe (migration 0028). A reader without the
view right on all of them, and on every type below them, gets `impact[].rows` as `null` and a summary and
messages without the counts; the `q` search matches the summary as that reader sees it. Records written before
the upgrade show their counts only to users who may view every type. A template install or reconcile run by a
user who may not view a type no longer counts its assets without a value in the first place.
