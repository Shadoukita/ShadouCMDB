### Security: confirming an authenticator is rate-limited, and unfinished set-ups expire

Anyone holding a user's session could guess the 6-digit code of an authenticator set-up the user had
started and abandoned, with no limit on attempts. A right guess turned on two-factor authentication
with the guessed secret, returned the recovery codes and marked the session as MFA-verified
([GH#408]).

- Wrong codes at `POST /api/v1/auth/mfa/totp/confirm` now count against the same per-user lock as
  wrong current passwords on the other MFA routes: from the 5th failure on, these routes answer
  `429 RATE_LIMITED` with `Retry-After`, from 1 s doubling up to 15 min. A right code clears the count.
- Each wrong code is audited as `mfa.failure` with `stage: "enrol_confirm"`.
- A set-up not confirmed within 15 minutes of being started expires: the confirm answers `409` and
  the user starts the set-up again (`POST /api/v1/auth/mfa/totp`).

**Upgrade:** no migration. Set-ups started more than 15 minutes before the upgrade must be started
again.

[GH#408]: https://github.com/Shadoukita/ShadouCMDB/issues/408
