### Security: import cell values are deleted with the file after 24 hours

24 hours after an import job's last activity the server deletes the uploaded file and its row
problems. Values read from the file stayed on the job record until then and were still returned by
`GET /api/v1/imports/{id}` for 90 days ([GH#390]). The same cleanup now also removes:

- the preview rows of the file (`file.previewRows`, up to 20 rows),
- the sample values of each column (`columns[].samples`),
- the planned changes of the dry run (`preview`, up to 50 rows, including the CI's old values).

The job record kept for 90 days after the job ended holds no cell values: the owner, file name,
format, size and SHA-256, the sheets, encoding and delimiter, the row and column counts, the column
names, the mapping (classes, attributes and options; it holds no values), the counts of the dry run
and commit, the status, any error and the timestamps. Jobs that expired before the upgrade are
cleaned the first time the cleanup runs (every 10 minutes). No API or database schema change.

[GH#390]: https://github.com/Shadoukita/ShadouCMDB/issues/390
