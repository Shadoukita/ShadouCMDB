### Security: `.env` is read from the current directory only

Without `--env-file`, `shadoucmdb` now loads `.env` from the current directory only, as `--help` always
said ([GH#482]). Previously it also searched every parent directory and loaded the first `.env` it found.
A command run from a subdirectory, including `migrate`, `restore`, `factory-reset` and `decommission`,
could therefore connect to the database named in another installation's `.env`, and a generated setup
token was written next to that file. Commands that read the configuration now log the absolute path of the env file loaded
(`loaded environment from /opt/shadoucmdb/.env`); values are never logged.

**Upgrade:** if you run `shadoucmdb` from a directory below the one holding `.env` and rely on it being
found, run it from that directory or pass `--env-file /path/to/.env`. Otherwise the command reports the
missing variable (for example `PGHOST is required when DATABASE_URL is not set`). `--env-file` is
unchanged. No schema change.

[GH#482]: https://github.com/Shadoukita/ShadouCMDB/issues/482
