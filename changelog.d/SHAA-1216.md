### Security: the Windows service runs as its own virtual account and can no longer change its settings

`shadoucmdb service install` registered the service as `NT AUTHORITY\LocalService`, and the install
guide gave that account Modify on the whole data folder (`C:\ProgramData\ShadouCMDB`). LocalService
is one account shared by many Windows services, so any of them could read the database credentials
and the encryption key, and rewrite `shadoucmdb.env` (for example `DATABASE_SSL=disable`)
([GH#435]).

- `service install` now defaults `--account` to the service's own virtual account,
  `NT SERVICE\ShadouCMDB` (`NT SERVICE\<name>` with `--name`), which no other service shares and which
  needs no password. `--account` still accepts any other account.
- The install guide (`deploy/windows/README.txt`) grants that account Read on `shadoucmdb.env` and
  `encryption.key`, and Modify only on `logs\` and the new `state\` folder, which holds the first-run
  setup token (`SETUP_TOKEN_FILE='C:\ProgramData\ShadouCMDB\state\setup-token'`). Administrators and
  SYSTEM keep full control; other users have no access.

**Upgrade (Windows only):** existing services keep running as LocalService until you switch them.
Follow "Upgrading an install whose service runs as NT AUTHORITY\LocalService" in
`deploy/windows/README.txt`: add `SETUP_TOKEN_FILE` to the env file, re-register the service with
`service uninstall` and `service install`, remove the LocalService entries with
`icacls <data> /remove:g 'NT AUTHORITY\LocalService' /T`, and grant `NT SERVICE\ShadouCMDB` the new
rights. Linux and container installs are not affected.
