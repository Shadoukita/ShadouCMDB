### Security: Workflow bootstrap needs the edit right; hidden workflows answer 404

`POST /api/v1/admin/workflow-definitions/{id}/bootstrap` without `dryRun` now needs the edit right
on every type the workflow covers, as starting a single instance does ([GH#694]). Before, a workflow
manager who could only view those types could start the workflow on all their CIs. They now get
`403 FORBIDDEN` and no instance is started. A dry run still needs only the view right, since it
counts only CIs and values that right already shows.

Bootstrap and `POST /api/v1/admin/workflow-definitions/{id}/instance-migrations` now answer
`404 NOT_FOUND`, the same as reading the workflow, when the caller may not view every type it
covers ([GH#695]). Before, bootstrap answered `409` or `403` and instance migration `403`, with a
message naming the workflow and, for bootstrap, whether it was published and active.

**Upgrade:** nothing to do. Scripts that run bootstraps as a manager with view-only rights on the
covered types need the edit right on them; integrations that expected `403` for a caller who may
not view the types should handle `404`.
