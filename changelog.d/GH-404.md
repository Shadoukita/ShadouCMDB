### Security: changing an import's file options takes the per-user import lock

`PATCH /api/v1/imports/{id}/file-options` queued a new analysis without checking whether the job's
owner already had an import running, so one user could queue any number of analyses at once and
keep the import worker busy for everyone else ([GH#404]). It now answers `429 import_busy` while
another import of the owner is running, like the upload, the dry run and the commit already do.

An analysis the worker gave up on with `internal_error` (after three attempts) could also be
started again with a fresh attempt count, which restarted a file that keeps failing the worker.
Changing the file options of such a job now answers `409 invalid_state`: delete the import and
upload the file again. Jobs whose analysis failed for another reason (for example the wrong sheet,
encoding or delimiter) can still be corrected as before. No database schema change; the OpenAPI
description of the endpoint lists the new `429` answer.
