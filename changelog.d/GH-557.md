### Security: the number of open connections is limited

Nothing limited how many TCP connections the API server kept open at once. Clients that opened
connections and never finished their request headers, or kept idle connections alive, could use up
the process's file descriptors; from then on every new connection failed, health checks included
([GH#557]).

The server now keeps at most 4 connections open per `HTTP_MAX_CONCURRENT_REQUESTS` slot (2,048 at
the default of 512), and never more than three quarters of its open-files limit (`ulimit -n`), so
descriptors remain for the database pool and import files. New connections past the limit are closed
at once, and a warning is logged at most every 10 seconds with the number refused. The limit in
effect is logged at start-up as `connection limit`.

**Upgrade:** nothing to do. If the server logs `connections refused: open connection limit reached`
under legitimate load, raise the service's open-files limit (for example `LimitNOFILE=` in systemd)
or `HTTP_MAX_CONCURRENT_REQUESTS`. No API or schema change.

[GH#557]: https://github.com/Shadoukita/ShadouCMDB/issues/557
