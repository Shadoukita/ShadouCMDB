### Documentation: restoring a large data model may need a higher `max_locks_per_transaction`

`restore`, `factory-reset` and `decommission` hold a lock on every object of the installation in one
transaction. On PostgreSQL's default `max_locks_per_transaction = 64`, a restore of a data model with about
1,000 CI types fails with `out of shared memory` (SQLSTATE 53200) and changes nothing. The backup and restore
section of the README now gives measured lock counts and recommends `max_locks_per_transaction = 256` for
data models over about 400 CI types ([GH#647]).

The backend test suite no longer fails with the same error on many-core machines at the default setting.

[GH#647]: https://github.com/Shadoukita/ShadouCMDB/issues/647
