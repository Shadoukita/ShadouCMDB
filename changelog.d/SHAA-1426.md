### Added: Workflow designer in Administration

Administrators holding **Manage workflows** (`workflows.manage`) now find **Administration › Processes ›
Workflows**, the web UI for the workflow definitions API. Running workflows on CIs comes in a later
release; until then a published workflow changes nothing for your CIs.

- **List.** Every workflow with its CI type, state field, status, current version and draft, searchable
  and filtered by type and status. The filters are in the URL, so a view can be bookmarked.
- **Settings.** Name, description, key and CI type (both fixed once created), the state field (fixed
  once a version is published), subtypes, auto-start and the active flag. Activating a workflow that
  drives a state field is confirmed first, and afterwards shows how many live CIs have no running
  instance yet: their state field stays locked until they are adopted with the workflow's bootstrap.
  A workflow that never ran can be deleted.
- **Designer.** The draft as a diagram (drag the states, or move them with the arrow keys) with tables
  of its states and transitions. Each state has a key, name, category, terminal flag and the state
  field's value it maps to; each transition its two states, whether a comment is required, the fields
  the operator fills in, and conditions on the CI's fields (all/any groups up to four levels). Every
  change is saved within a second and checked: problems show on the state or transition they are about,
  and publishing is offered only for a saved draft without errors. Publishing takes an optional change
  note. A draft can be discarded, and a new one started from the current version.
- **Versions.** Every version with its status, counts and running instances; a published version can
  be viewed read-only and retired.
- **Grants.** A matrix of transitions (and cancelling an instance) × permission profiles, saved as a
  whole. Without the right to list profiles, the profiles already granted are shown and others are added
  by name.

**Upgrade:** nothing to do.
