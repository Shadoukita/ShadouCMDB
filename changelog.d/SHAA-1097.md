### Security: Directory sign-ins are throttled per directory entry, not only per typed name

The sign-in lock counted failures under the name as typed. A directory may resolve many spellings
to the same entry (OpenLDAP and Active Directory normalise case, width and some invisible
characters, and a user filter may also match `mail` or `userPrincipalName`), so each spelling got
its own five free failures and its own account lock ([GH#406]).

- **Per entry:** once a directory finds an entry, failed sign-ins are also counted under that entry
  (the directory and the entry's `objectGUID`, `entryUUID` or DN), with the same free failures,
  backoff and per-network rules as the name's lock. While an entry is locked its password is not
  checked: the sign-in gets the same `401` as a wrong password, so the answer does not reveal which
  names find an entry, and it is audited as `login.failure` with `reason: "directory_entry_locked"`.
- **Names looked up:** only names an account can have (letters, digits and `. _ @ -`, at most 64
  characters, leading and trailing spaces ignored) are sent to a directory. Any other name is
  answered like an unknown name, without a directory search.

**Upgrade:** users who sign in to a directory with a name that has spaces or non-ASCII characters
(for example a `cn` matched by the user filter) must use their account name (`sAMAccountName`,
`uid`) or `userPrincipalName` instead. The usual filters on those attributes are not affected.
