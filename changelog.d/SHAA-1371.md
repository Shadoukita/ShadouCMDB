### Fixed: large configuration imports no longer slow down with every audited change

Every audit log row used to rewrite the audit hash-chain head, and within one transaction each rewrite
made the next audit row slower ([GH#487]). A configuration import, which records all of its changes in
one transaction, therefore took time that grew with the square of its size and held the import lock and
a database connection for minutes; a dry run creating about 200,000 lookup values took over nine
minutes. Migration 0040 moves the head once per transaction, at commit, so audit rows cost the same
however many a transaction writes (40,000 audit rows in one transaction: 12 s before, 2.4 s after, on a
test system).

The audit trail itself is unchanged: rows are hashed and chained exactly as before, chain order is still
commit order, existing chains need no rewrite, and `shadoucmdb audit-verify` reports deleted, altered or
re-linked rows as before.

**Upgrade:** run `shadoucmdb migrate` with `MIGRATION_DATABASE_URL` set, as for every upgrade; no
manual SQL is needed.
