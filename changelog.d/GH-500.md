### Fixed: a configuration import no longer blocks sign-ins while it runs

A configuration import (`POST /api/v1/admin/config/import`), including a dry run, wrote its audit
entries as it went. Each audit entry locks the head of the audit log's hash chain until the
transaction ends, so every other audited action, every sign-in included, waited for the whole
import. A large legacy file kept sign-ins waiting until they failed with a server error after the
database statement timeout ([GH#500]).

A dry run now writes no audit entries at all (it is rolled back, so it never recorded any). An
applied import keeps its audit entries in memory and writes them all just before it commits, so
the chain head is locked only for that final step. The audit trail of an applied import is
unchanged: the same entries, with the same actor and request id, in the same order.

[GH#500]: https://github.com/Shadoukita/ShadouCMDB/issues/500
