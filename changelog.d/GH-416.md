### Security: Hardening from the security review: planted code, unencrypted secrets, error text, headers

Defence-in-depth changes from an internal security review ([#416]):

- **Migrations refuse planted code.** On a three-role installation the API role owns the area
  schemas and the type tables, and migrations write to them as the schema owner. `shadoucmdb
  migrate`, `restore` and `factory-reset` now stop before changing the schema when the API role's
  schemas or tables carry a trigger, a rule, row-level security or a policy, or when a function
  lives in those schemas or is owned by the API role. ShadouCMDB creates none of these, and the
  error lists every object it found.
- **Unencrypted secrets are refused at sign-in.** An authenticator secret or identity provider
  secret stored without encryption is no longer used for sign-in; `serve` encrypts such secrets at
  start-up, as before. `shadoucmdb verify` and `migrate` print a warning while any are left.
- **Import errors no longer show internal detail.** When a stored import file cannot be read, the
  import shows a fixed message; the cause is written to the server log only.
- **`Cross-Origin-Resource-Policy: same-origin`** is sent on every response, except the public
  logo and favicon, which other origins may still embed.
- The builder stages of the root `Dockerfile` are pinned by digest.

**Upgrade:** nothing to do on a standard installation. If `migrate` refuses with a list of
objects, find out who created them, drop them as the schema owner, and run `migrate` again.
