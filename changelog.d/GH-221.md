### Security: field changes checked against stored values need view on those values

Since [GH#180] a refused field change no longer quoted stored values to a user without the view right on the
field's type, but it still said how many values stood in the way. With the change preview, which changed nothing
and left no audit entry, a user with the data-model permission could still find out, one guess at a time, which
values the assets of a type they may not view store, and how many assets that type holds ([GH#221]).

A change whose outcome depends on stored values (a field's data type, or a new enum value list on an existing
field) now needs the view right on the field's type and every type below it. Without it, both the change and its
preview are refused with `403 FORBIDDEN` (`view_required`) before any value is read, so the answer is the same
whatever is stored. Such a refused preview is recorded in the audit log as `schema_change.refused`, with the user,
the field and the change they tried. A refusal to make a field required no longer tells these users how many
assets lack a value.

**Upgrade:** migration 0027 adds the `schema_change.refused` audit event (kept with the change history;
`prune-audit --scope changes` removes it). Data-model managers without the view right on a type now need a user
who can view it, or the view right, to change the data type or value list of its fields. Check the permission
profiles of your data-model managers.
