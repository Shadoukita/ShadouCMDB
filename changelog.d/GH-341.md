### Security: A second-factor sign-in racing an MFA reset or disable no longer opens a session

Resetting a user's two-factor authentication, or the user turning it off, ends all of that user's
sessions ([GH#280]). A sign-in whose authenticator code or recovery code was accepted just before
the reset or disable committed could still open a session just after it ([GH#341]), marked as
having proven the second factor.

Opening a session after a second-factor check now locks the user's authenticator and checks that it
is still there. A sign-in that started first opens its session before the reset or disable goes
ahead, and the reset or disable ends that session. A sign-in that has to wait for the reset or
disable gets no session. It is refused with `401 UNAUTHENTICATED` ("Two-factor authentication was
reset or turned off for this account during the sign-in"), and a `login.failure` audit row with
`reason: "mfa_removed"` is written. The user signs in again with their password.

**Upgrade:** nothing to do; no configuration or schema change.
