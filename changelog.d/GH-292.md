### Security: setting up an authenticator ends the password-only sessions

A session opened with the password alone and left limited by `requireMfa` after the user set up an
authenticator in another session could still use the set-up routes, including
`PUT /api/v1/auth/password`. Changing the password from it ended the user's verified sessions and
revoked their API tokens ([GH#292]).

- Confirming an authenticator (`POST /api/v1/auth/mfa/totp/confirm`) now ends the user's other
  sessions that did not prove a second factor, with or without `requireMfa`. Each is audited as
  `session.revoke` with `reason: "mfa_enrolled"`. The session that confirmed the authenticator and
  sessions signed in with a code are kept. Users of the ended sessions sign in again with a code.

**Upgrade:** no migration.
