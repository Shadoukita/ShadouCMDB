### Security: Changing your own password or setting up two-factor authentication renews your session

`PUT /api/v1/auth/password` and `POST /api/v1/auth/mfa/totp/confirm` now replace the calling
session with a new one (new session id, session cookie and CSRF token) in the same transaction,
and set both cookies again on the response. Before, the calling session kept its id, so a copy of
its cookie obtained before the change kept working afterwards, and after an authenticator was
confirmed it even counted as having proven the second factor. The old session is audited as
`session.revoke` with reason `rotated` and `replacedBy` naming the new session. The web UI picks up
the new CSRF token by itself.

**Upgrade:** API clients that sign in with a session cookie and call either route must take the
cookies from the response (or read the new CSRF token from `GET /api/v1/auth/me`) afterwards; the
old cookie answers `401`.
