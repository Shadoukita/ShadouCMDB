### Security: a directory that drops packets no longer reveals local account names by response time

While an enabled LDAP/AD directory silently dropped packets (firewall DROP, host gone, broken
route), a sign-in with an unknown username waited for the 10-second LDAP timeout. A local account's
wrong password was answered after `SIGN_IN_FAILURE_FLOOR_MS`. The answers were identical, but the
response time showed which names are local accounts ([GH#570], [GH#595]).

After a password-form lookup times out, ShadouCMDB now stops asking that directory during sign-in.
Only the sign-in that ran into the timeout waits for it. The first sign-in after 30 seconds starts a
background check (connection, service account bind and a user search) and is answered without
waiting for it. If the directory answers the check, sign-ins ask it again. If it still does not
answer, the directory is skipped for another 30 seconds. While the directory is skipped:

- Unknown names get the same `401` as before, held to the floor and audited as `login.failure`
  with `reason: "directory_unavailable"`. A local account's wrong password takes the same time.
- Directory accounts get the `503` (`IDENTITY_PROVIDER_UNAVAILABLE`) at once. After the directory
  recovers, they can sign in again as soon as a background check has succeeded.
- The server log shows `LDAP directory skipped: a lookup timed out, asked again 30 s later`, and the
  result of each background check.
- Each server process tracks this separately. Changing the directory's URL, or a successful
  connection test under Administration › Identity providers, ends the skip immediately.

The one sign-in that first runs into the timeout still takes about 10 seconds, so each outage reveals
at most one name per server process.

A directory that refuses connections (closed port, TLS failure) fails fast and is not skipped.
