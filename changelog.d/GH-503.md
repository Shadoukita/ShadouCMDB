### Security: Import job reads that are audited need the CSRF token

Reading an import job, its problem list or its error report as an administrator who does not own
the job writes an `import.report_read` audit row. These three GETs (`GET /api/v1/imports/{id}`,
`GET /api/v1/imports/{id}/issues` and `GET /api/v1/imports/{id}/error-report`) did not check the
CSRF token. The session cookie is sent with a cross-site link, so a link on another site could
write that audit row in the administrator's name. A browser session now has to send the
`X-CSRF-Token` header on them, as on a write. Without it the API answers `403 CSRF_TOKEN_INVALID`
and records nothing. The web UI sends the token.

**Upgrade:** scripts that sign in with a session and read import jobs must send the `X-CSRF-Token`
header (the `csrfToken` from the sign-in response) on these GETs, as they already do on writes.
