### Security: configuration exports are recorded in the audit log

Downloading the configuration file (`GET /api/v1/admin/config/export`) left no trace in the audit
log, although the file carries the whole data model, the permission profiles (for callers who may
read them), the UI settings and the saved import mappings ([GH#407]). Every download now writes one
`export` entry with entity type `config` (entity id: the nil UUID), attributed to the user or API
token that made it. Its new value names the sections included (`sections`), whether permission
profiles were in the file (`profilesIncluded`) and how many import mappings were (`mappingCount`),
never the content. The audit log list filter accepts `entityType=config`. `prune-audit --scope
changes` covers these entries; the default `auth` scope does not.

**Upgrade:** nothing to do; no migration.
