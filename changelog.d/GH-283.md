### Security: the documented Caddy and nginx examples buffer request bodies and limit sign-in rates

The Caddy example in the hardening checklist did not buffer request bodies, as Caddy's
`reverse_proxy` streams them by default ([GH#283]). Behind it, one client could open many sign-in
requests, send only the first byte of each body, and hold the anonymous request pool (one eighth of
`HTTP_MAX_CONCURRENT_REQUESTS`) for up to `HTTP_HEADER_READ_TIMEOUT_SECS`, so every other sign-in was
answered `503 SERVER_BUSY`. The earlier nginx example limited bodies to 1 MiB, so configuration
imports above that size got `413`.

The Caddy example now sets `request_body { max_size 16MiB }` and `request_buffers 17MiB` (the buffer
must be larger than the size limit, or Caddy streams the rest). The nginx examples set
`client_max_body_size 16m` and `proxy_request_buffering on` explicitly, and rate-limit the sign-in,
OIDC and first-run setup routes per client address with `limit_req`. No server, API or schema change.

**Upgrade:** if your proxy configuration was copied from the Caddy example, add the `request_body`
and `request_buffers` lines to it. If it was copied from the nginx example, raise
`client_max_body_size` to `16m`. With any proxy, check that it buffers whole request bodies and
rate-limits `/api/v1/auth/*` per client address, as described in the documentation's
"Reverse proxy" and "Hardening checklist" pages.
