### Security: attribute validation patterns have a size limit

A text attribute's `validation.pattern` was compiled with the regular-expression library's default
limit of 10 MiB, and every pattern sent in a request was kept in a process-wide cache of up to 1000
entries, even when the request was refused or rolled back. A user with `datamodel.manage` could send
short patterns such as `\w{180}x1`, `\w{180}x2`, … and make the server hold about 10 MiB per
pattern, up to roughly 10 GiB ([GH#412]).

A pattern must now compile to at most 1 MiB. Larger ones are refused with `400 VALIDATION_ERROR`
and code `invalid_format` on `validation.pattern`. Checking a pattern in a request no longer caches
it; only patterns applied to stored attribute values are cached, and the cache is limited to about
64 MiB as well as 1000 entries. Patterns such as `\w{20}`, `.{0,500}` and those of the built-in
templates are unaffected. The limit mainly affects long bounded repetitions of Unicode classes
(`\w{n}`, `\p{L}{n}`); `(?-u)\w{n}` or an unbounded `\w+` with a `maxLength` are much smaller.

**Upgrade:** a pattern stored before this release that exceeds the limit is no longer applied to
values. The server logs a warning naming the pattern; edit the attribute definition to use a
smaller pattern.
