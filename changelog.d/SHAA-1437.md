### Security: An unreachable directory no longer tells which sign-in names are local accounts

While an enabled LDAP/AD directory could not be reached, `POST /api/v1/auth/login` answered a name
no account has with an immediate `503 IDENTITY_PROVIDER_UNAVAILABLE`, but a local account's wrong
password with a held `401`. The 503 was not counted by the sign-in throttle and not audited, so
anyone could list which names are local accounts, at full speed, for as long as the directory was
down ([GH#499]).

- **Same answer:** a name no account has now gets the `401 UNAUTHENTICATED` a wrong password gets,
  held to `SIGN_IN_FAILURE_FLOOR_MS`, counted by the throttle, and audited as `login.failure` with
  `reason: "directory_unavailable"`. A directory user who has never signed in before sees
  "Invalid username or password" until the directory is reachable again; the server log records
  the directory error.
- **Directory accounts:** an account that already belongs to the directory still gets
  `503 IDENTITY_PROVIDER_UNAVAILABLE`. Its password is not checked, so the attempt is not counted
  and the user is not locked out by retrying during the outage.
