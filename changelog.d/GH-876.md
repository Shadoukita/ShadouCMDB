### Security: one notification action run examines at most ten times the recipient cap

Since [GH#848], `WORKFLOW_ACTIONS_MAX_RECIPIENTS` counts only the users who are notified. Users left
out (inactive, `no_view`, the actor, already told by the built-in notification) were still each
given a delivery record and a permission lookup, so the work of one run grew with the size of the
user directory rather than the cap: a profile of 3,000 users who may not view the CI's type wrote
3,000 skipped deliveries under a cap of 100 ([GH#876]). A run now examines at most ten times
`WORKFLOW_ACTIONS_MAX_RECIPIENTS` users, in id order, told or skipped. Past that it ends `truncated`,
as it does when the cap is reached, even if fewer users than the cap were notified. The action
preview still counts every user it would notify, so it can report more `included` users than such a
run reaches.

**Upgrade:** nothing to do. An action whose recipients are mostly users who are never notified may
now reach fewer of the rest; narrow its recipient sources or raise `WORKFLOW_ACTIONS_MAX_RECIPIENTS`.
