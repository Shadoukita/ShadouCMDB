### Fixed: password length errors use the password policy message

A new password that is too short or too long is now refused with the policy message ("Must be at
least 12 characters" / "Must be at most 256 characters", code `password_policy`), not with the
generic length text (code `too_small` / `too_big`). This applies to every new-password field: first-run
setup, creating a user, an administrator's password reset and changing your own password. Password
fields are now marked `format: password` in the OpenAPI document. The web UI now counts characters the
way the server does, so a password of emoji is no longer let through by the browser and then refused.

**Upgrade:** nothing to do. Scripts that matched the `too_small` / `too_big` codes on password fields
should match `password_policy`.
