### Security: the relationship graph no longer reads every relationship of a hub CI

`GET /api/v1/configuration-items/{id}/graph` limited the CIs it returned with `maxNodes`, but
read every live relationship of every CI it reached, on every hop. A CI with tens of thousands of
relationships (a core switch, a shared database) made each graph request load all of them, so any
user who can view it could put heavy load on the API and the database by repeating the request
([GH#185]). A graph request now reads at most 5 × `maxNodes` relationships over all hops (5,000 at
the maximum `maxNodes` of 1000). When that limit is reached the response has `truncated: true`, the
same flag that `maxNodes` already sets.

**Upgrade:** nothing to do. No schema change. Graphs of CIs with more relationships than the limit
now come back truncated; open the graph from a CI further out, or use the relationship list of the
hub CI, to see the rest.

[GH#185]: https://github.com/Shadoukita/ShadouCMDB/issues/185
