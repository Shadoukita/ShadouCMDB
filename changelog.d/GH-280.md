### Security: requireMfa follows what each session proved

With `requireMfa`, a session was limited to the MFA set-up routes only while its user had no
authenticator. A session opened with the password alone therefore got full access as soon as the
user set up an authenticator in another session, and again after an administrator reset their MFA
and they set it up again ([GH#280]).

- **Per session:** a local or directory (LDAP) session under `requireMfa` has full access only if
  its sign-in proved a second factor (authenticator or recovery code), or if the authenticator was
  set up in that session. Other sessions stay limited (`403 MFA_ENROLMENT_REQUIRED`, and
  `mfa.enrolmentRequired` in `/auth/me`) until the user signs in again with a code.
- **Reset and turn-off end sessions:** an administrator's MFA reset
  (`DELETE /api/v1/admin/users/{id}/mfa`) ends every session of the user (the administrator's own
  is kept when they reset themselves); turning one's own MFA off ends one's other sessions. Each is
  audited as `session.revoke` with `reason: "mfa_reset"` or `"mfa_disabled"`.

**Upgrade:** no migration. After the upgrade, users under `requireMfa` whose current session was
opened before they set up their authenticator are asked to sign in again with a code.
