### Added: Running workflows from the web UI

Published workflows can now be run on CIs from the web UI (the runtime API of SHAA-1424). Every screen
shows only instances on CIs of types you may view, and only the transitions you are granted.

- **CI page › Workflows.** A tab on every CI that has run a workflow, or on which you may start one. It
  lists the running instances first, then the ones that ended last, with their state, who started them
  and when they last moved. **Start workflow** offers the active workflows of the CI's type (needs the
  edit right on the type).
- **Transitions.** Each running instance offers the transitions you are granted. Running one opens a
  dialog with the transition's fields, using the same inputs as the CI form and filled with the CI's
  values, and a comment (required when the transition says so). A transition whose conditions fail on
  the CI's current values is still offered, marked, with the reasons: a value entered in the dialog may
  meet them. A refused step shows each problem next to its field. When someone else moved the instance
  on in the meantime, the dialog says so and offers to reload it. Instances can be cancelled with a
  reason by those who may.
- **Workflows page** (main menu, under Inventory). Every instance with filters for workflow, state,
  status and CI type, sortable by start and last step; the filters are in the URL. Above it, the running
  instances counted per workflow and state; a count lists those instances.
- **Instance page.** The instance, the states and transitions of the version it runs on, and its history:
  every start, step, cancellation and forced state with who, when, the comment and the fields it changed.
  Holders of **Manage workflows** can force an instance into another state, with a reason.
- **CI history.** Workflow starts, steps, cancellations and forced states appear in the CI's History
  tab with the workflow, the transition, the states, the comment and the changed fields, linked to the
  instance.

Not yet in this release: the read-only state field while a workflow drives it, and the bootstrap action
for existing CIs. They follow with the backend slice that adds them (SHAA-1698).

**Upgrade:** nothing to do.
