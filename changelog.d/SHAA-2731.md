### Added: groundwork for workflow actions and notifications (schema, `webhooks.manage`, e-mail language)

This release prepares workflow actions: e-mail, outbound webhooks, in-app notifications and attribute
updates on a transition (SHAA-2725). Nothing is sent and nothing changes in how workflows run until
those actions can be configured, which a later release adds.

- Migrations 0073 and 0074 add the tables for attribute actions (part of a workflow version),
  notification actions and their recipients (on the workflow), webhook endpoints and the webhook host
  allowlist, and the outbox that delivers notifications after a transition commits. A trigger on the
  workflow event table records one outbox run per matching notification action, in the transition's
  own transaction, so a transition that is rolled back sends nothing. Events from before the upgrade
  never fire an action.
- New global right **`webhooks.manage`** (Manage webhooks): webhook endpoints and the hosts they may
  reach. Only the Administrator profile holds it, implicitly. Grant it to other profiles only for the
  people who decide where CMDB data may be sent outside ShadouCMDB.
- `PATCH /api/v1/auth/me` with `{"locale": "en" | "de" | null}` sets the language of the e-mails a
  user receives. `GET /api/v1/auth/me` returns it as `locale`. A change is audited as an `update` on
  the user.
- New audit actions, reserved for the slices that write them: `webhook_endpoint.rotate_secret`,
  `webhook_endpoint.suspend`, `webhook_endpoint.resume`, `workflow.action_dead`,
  `workflow.action_retry`, `workflow.action_discard`, `workflow.action_suppressed` and `mail.test`.
  New audit entity types: `webhook_endpoints`, `webhook_allowed_hosts` and
  `workflow_action_deliveries`. Delivery entries name their CI. An auditor who may not view that CI's
  class does not see them, as for notes on a CI. `prune-audit --scope changes` covers the new actions.
- New error codes in the API contract: `WORKFLOW_ACTION_INVALID` (422), `WEBHOOKS_DISABLED` (409)
  and `MAIL_NOT_CONFIGURED` (409).
- **`shadoucmdb restore` sends nothing:** after loading a backup, it cancels every workflow
  notification that was still to be sent and suspends every webhook endpoint with reason `restored`.
  The restore output says how many. A production backup restored into a test system therefore neither
  repeats e-mails nor posts to production receivers. An administrator resumes the endpoints
  deliberately.

**Upgrade:** nothing to do. 0073 changes no existing table's data and does not rewrite the workflow
event table, so it is quick on large installs. 0074 validates the extended audit log checks in a
transaction of its own while the API keeps writing.
