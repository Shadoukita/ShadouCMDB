### Changed: Record details and relationships are layout sections; field separators

Detail page layouts place the record details (class, created and last changed) and the relationships
as sections like any other: section kinds `record` (new) and `relations`, each at most once per layout.
An administrator can move or remove them; a layout with tabs shows them only where it places them, so
there is no implicit "Record" section or relationships panel after the layout any more. Field sections
can also hold separators (`{ "separator": true, "label": "…" }`): a line across the section with an
optional heading, which holds no field.

The UI settings document carries `layoutFormat` (now 3). A document sent without it (an older
configuration export, an older settings version being restored, an API client written before this
release) is converted on save as described below, so it shows what it showed before.

**Upgrade:** migration 0048 adds a "Record" section and, where none is placed, a "Relationships"
section at the end of the first tab of every layout template, class layout and CI layout that has
tabs, so every detail page looks as before. The converted settings are saved as a new settings version
and every change is audited with actor `migration 0048`. Layouts without tabs keep the built-in
arrangement. No action needed; remove the sections in the layout editor where you do not want them.
