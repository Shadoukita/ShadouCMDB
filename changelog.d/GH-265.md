### Security: data-model usage counts, lookup retire refusals and type purges no longer count CIs the user may not view

A user with the data-model permission but the view right on only some CI types could learn how many CIs of the
other types exist, hold a field value or a lookup value, or are joined by a relationship
([GH#265], [GH#266], [GH#268]):

- `GET …/{id}/usage` of CI types, fields, relationship types and rules, lookup list values and the deprecated
  statuses, environments, locations and owners, and the `409 IN_USE` answer of their `DELETE`;
- the `409 IN_USE` refusal to retire a lookup value while CIs store one of its dependent values
  (`PATCH /api/v1/lookup-list-values/{id}` and configuration import);
- the relationship count of a type purge (preview, recorded schema change and audit log), which included
  relationships to CIs of other types. A purge refused because other types' CIs still reference the type's CIs
  no longer repeats the PostgreSQL error, which named the referencing table; the server log keeps it.

These counts are now told only to a user who may view every CI type they can include. Whether a row is in use,
and whether a delete or retire is refused, is decided exactly as before. Administrators and users who may view
every type see no change. The API change is described under *Changed (breaking API change)*.
