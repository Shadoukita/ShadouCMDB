### Added: outbound webhooks for workflow actions

Workflow actions can now post a signed JSON envelope to an external receiver, such as an ITSM tool, when
a transition runs or an approval event happens. Webhooks are **off by default**: the operator turns them
on with `WEBHOOKS_ALLOWED=true` and sets the ceiling administrators work inside (`WEBHOOK_ALLOWED_HOSTS`,
`WEBHOOK_ALLOW_PRIVATE_CIDRS`, `WEBHOOK_ALLOW_HTTP`, `WEBHOOK_PROXY`, `WEBHOOK_PROXY_PASSWORD_FILE`,
`WEBHOOK_TLS_CA_FILE`; see `.env.example`).

- New endpoints under `/api/v1/admin/webhook-endpoints` (list, create, read, `PATCH`, delete,
  `rotate-secret`, `ping`, `pause`, `resume`) and `/api/v1/admin/webhook-allowed-hosts`. They need the new
  right `webhooks.manage`. Every change is audited.
- **Signing.** Each request carries `X-ShadouCMDB-Signature: t=…,v1=…`, an HMAC-SHA256 of the timestamp
  and the raw body. The signing secret is shown once. After a rotation, the previous secret also signs for
  a grace period (`graceHours`, default 24, at most 168), so receivers can switch without losing
  deliveries. The README describes how to verify a request. The envelope (`specVersion` `1`) is described
  by `backend/src/modules/webhooks/payload.schema.json`.
- **Server-side request forgery protection.** The receiver's host must be on the administrator's
  allowlist, which stays inside the operator's ceiling. Each address the host resolves to is checked on
  every request, and the connection goes to the checked address. Loopback, private, link-local, CGNAT,
  multicast and reserved ranges are refused, including their IPv4-mapped and NAT64 forms, unless the
  operator opens a network with `WEBHOOK_ALLOW_PRIVATE_CIDRS`. Cloud metadata addresses are always
  refused. Redirects are not followed. Plain `http://` needs both `WEBHOOK_ALLOW_HTTP=true` and an
  allowlist entry that allows it. A URL may not carry `user:password@`: receiver credentials go in the
  endpoint's authentication header, which is stored encrypted.
- **Limits.** A connect timeout of 5 seconds and a per-endpoint request timeout, at most 64 KiB of an
  answer read, per-endpoint limits on requests in flight and per minute, and a circuit breaker: after 20
  failures in a row with no success for 15 minutes the endpoint is suspended, its deliveries are held, an
  audit entry is written and holders of `webhooks.manage` get an in-app notice. `resume` releases the
  held deliveries.
- **Secrets.** The signing secrets and the authentication header value are encrypted with the encryption
  key. They are covered by the start-up key check, are re-encrypted at start-up after a key rotation
  (`ENCRYPTION_KEY_PREVIOUS_FILE`), are counted in the backup header, and have their own
  `shadoucmdb webhooks reset-undecryptable` for a lost key (it suspends the endpoints as
  `secret_required` with a new signing secret). They never appear in an API response after creation, in the audit
  trail, in a configuration export or in the log.
- **Payload content.** `settings.includeAttributes` takes only fields of the workflow's CI type or its
  ancestors, and at send time only those of the CI's current type are read. If a receiver repeats the
  request in its error answer, that excerpt is not stored on the delivery: only the status is kept.
- **Echo-loop cause (GH#845).** `X-ShadouCMDB-Cause` is now taken only from API tokens, and only when it
  names a webhook delivery that was sent for the same workflow instance within
  `WORKFLOW_ACTIONS_MAX_AGE_HOURS`. Any other value is ignored. Before this change, any user who could
  run transitions could send made-up causes and have an instance's notification actions suppressed as an
  echo loop.
- **Configuration transfer.** Format version 14 also carries the webhook endpoints and the host
  allowlist, without secrets. An import creates new endpoints `suspended` (`secret_required`) until their
  secret is rotated on the target instance.

**Upgrade note.** Migration 0076 changes the key-id columns of `cmdb.webhook_endpoints` to `integer`,
adds checks on the encrypted columns and refuses URLs with credentials (GH#836). The table was created
empty by 0073 and nothing wrote it before this release; if rows were inserted by hand, the migration
stops with a message asking to delete them first.
