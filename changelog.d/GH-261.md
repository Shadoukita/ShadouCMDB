### Security: the audit log shows schema change counts only to readers who may view the types counted

Since [GH#252] the schema change history hides how many values or rows a change counted from readers who may
not view every type concerned. The audit entry each schema change leaves (`GET /api/v1/audit-log`, `entityType`
schema_changes) still held the full record, so a user with `audit.view` whose profile limits the types they may
view could read the counts there ([GH#261]).

These entries now show `summary` and `impact` exactly as `GET /api/v1/schema-changes/{id}` shows them to the
same caller: without the counts unless the caller may view every type they describe. Entries for changes
recorded before migration 0028 show their counts only to users who may view every type. The response shape is
unchanged; the audit log itself is not modified.
