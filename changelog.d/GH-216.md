### Security: refused sign-ins take a fixed minimum time, so response times no longer reveal local accounts

With an LDAP/AD directory enabled, a refused sign-in took longer for a name no local account has
(the directory was asked first) than for a local account's wrong password, so response times told
which names are local accounts ([GH#216]). Every refused sign-in (`401` from
`POST /api/v1/auth/login`: wrong password, unknown name, disabled account, directory refusal) is now
answered no earlier than a fixed floor after the throttle let it through, with a little random
jitter. The failure is counted and audited before the wait, and the wait holds no database
connection and no request capacity. Successful sign-ins, `MFA_REQUIRED`, `429` and `503` answers are
not delayed.

**Upgrade:** nothing to do. The floor is 1 second by default; `SIGN_IN_FAILURE_FLOOR_MS` (0 to 10000)
changes it. With a directory whose sign-ins can take longer than a second, raise it above the
slowest one. No API or schema change.
