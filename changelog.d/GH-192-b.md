### Security: `__Host-` session cookies behind HTTPS; optional OIDC host allowlist

Behind HTTPS the session and CSRF cookies are now named `__Host-shadoucmdb_session` and
`__Host-shadoucmdb_csrf` ([GH#192]). Browsers accept a `__Host-` cookie only from the host itself, with
`Secure`, `Path=/` and no `Domain`, so another host under the same domain can no longer plant a session
cookie for ShadouCMDB. When a request carries both names, only the `__Host-` cookie is read. Plain HTTP
setups (`COOKIE_SECURE=never`, or `auto` without HTTPS) keep the old names.

The new `OIDC_ALLOWED_HOSTS` setting limits the hosts the server contacts for OIDC sign-in: the
discovery URL, and the token endpoint and key set the discovery document names. Host names match
exactly, never as a suffix. Unset (the default), any host is allowed, as before. See
[deployment.md](docs/deployment.md#hardening-settings).

**Upgrade:** nobody is signed out. Sessions opened before the upgrade still work over HTTPS by their
old cookie name. The first answer to such a session sets the `__Host-` cookies and deletes the old ones.
This fallback is removed in the release after this one. Scripts that sign in with a password and read
the cookie by name must accept the `__Host-` names over HTTPS (API tokens are unaffected). Do not
rewrite cookie names, `Path` or `Domain` at the reverse proxy. To use `OIDC_ALLOWED_HOSTS`, list every
host your OIDC providers use, then run each provider's connection test.
