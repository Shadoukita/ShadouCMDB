### Security: `token.use` audit rows no longer show ids of CIs the reader may not view

Every request made with an API token writes a `token.use` audit row holding the request path. A
path such as `/api/v1/configuration-items/<id>/graph` carries the id of the CI requested, so any
user with `audit.view` saw the ids of CIs in classes they may not view, and which token owner
touched them when ([GH#270]).

For a reader whose profile limits the classes they may view, `GET /api/v1/audit-log` now replaces
that id with `{hidden}` (e.g. `/api/v1/configuration-items/{hidden}/graph`) when they may not view
the CI, or both endpoints of a relationship (`/api/v1/relationships/{hidden}`). The rest of the row
(token, owner, outcome, method, time) is unchanged. The path is judged when it is read, so rows
written before the upgrade are covered too. Readers who may view every class, and the SIEM export
(`AUDIT_EXPORT`), still get the path as recorded. No configuration change.
