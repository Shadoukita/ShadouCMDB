### Security: a configuration file holds at most 25,000 lookup values

An applied configuration import (`POST /api/v1/admin/config/import?mode=apply`) writes its audit
rows just before it commits, and while they are written every sign-in and every other audited change
waits. A file within the 16 MiB size limit could carry about half a million lookup values, which held
sign-ins for around 15 seconds ([GH#546]). A file now holds at most 25,000 lookup values in all,
counting the rows of the former `statuses`, `environments`, `locations` and `owners` sections of
0.1.0-rc.1 files. A larger file is refused with 400 `VALIDATION_ERROR` (code `too_big` at `lookups`)
before anything is read or changed, for dry runs too. At the limit the audit rows take under a second
to write.

**Upgrade:** nothing to do for typical installs. If an export of yours carries more than 25,000
lookup values, split its `lookups.lists` across several files and import them one after the other;
an import never deletes, so the lists of earlier files stay in place.

[GH#546]: https://github.com/Shadoukita/ShadouCMDB/issues/546
