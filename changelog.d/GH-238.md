### Security: moving an identity provider needs its secret again

A change to an identity provider that points it somewhere else now has to include the stored secret
again ([GH#238]). Before, `PATCH /api/v1/admin/identity-providers/{id}` kept the stored OIDC client
secret or LDAP bind password when only the address changed, so an administrator could send it to a
server of their choice (in the LDAP connection test, or the OIDC code exchange) and read it there,
although the API never shows it.

Now such a patch is refused with `422 SECRET_REQUIRED` and nothing is changed when it changes
`oidc.issuerUrl`, the scheme, host or port of `ldap.url`, or `ldap.bindDn` without sending
`oidc.clientSecret` or `ldap.bindPassword`. `details[]` names that field with code
`secret_required`. Changes that keep the server (a trailing slash, the default port written out,
another letter case in the host) need no secret, and neither does a provider with no stored secret.

**Upgrade:** API clients and scripts that move a provider to another server must send its secret
in the same request.
