### Fixed: a workflow action run whose fan-out keeps failing gives up and is audited (GH#846)

A notification action run whose fan-out failed every time was retried every minute with no end. It
was never audited and never removed. It did not count towards the queue limit, and it could notify
users days late.

- Migration 0078 adds an attempt counter to workflow action runs. Each fan-out attempt counts.
- After `WORKFLOW_ACTIONS_MAX_ATTEMPTS` failed fan-out attempts, the run is cancelled with reason
  `fan_out_failed`. A run that is not fanned out within `WORKFLOW_ACTIONS_MAX_AGE_HOURS` is cancelled
  with reason `expired`. Deliveries already behaved this way. Each cancelled run writes a
  `workflow.action_dead` audit entry on its workflow, with actor `system`. The entry records the run,
  action key, kind, CI, reason and attempts.
- Runs being fanned out now count towards `WORKFLOW_ACTIONS_QUEUE_MAX`.
