### Changed: Administration edit pages for users, groups and permission profiles

- **One way to save:** the user, group and permission profile pages now save the same way as a configuration item. A bar at the bottom of the window stays in view while you scroll. It shows **Unsaved changes** with the number of changed fields, and offers **Cancel**, **Discard** and **Save changes**. A successful save is confirmed by a notification. Validation errors still appear next to the field. Leaving a page with unsaved changes asks first.
- **Title row:** each page starts like a configuration item: an icon, the name, and a line with the key facts (for a user: status, display name, two-factor, sign-in source and last sign-in; for a group: members and last change; for a profile: Built-in, two-factor requirement, users holding it, creation date and last change).
- **Delete** for a user, a group or a permission profile has moved into the **More actions** (`⋯`) menu in the title row. The confirmation is unchanged and still says what is affected. Disabling a user stays in the **Access** panel.
- **Permission matrix:** the class permissions are grouped into **Read** (View) and **Change** (Create, Edit, Delete). The class column and the column headers stay in view while the matrix scrolls, so large data models stay readable.
- **API token dialog:** the secret has a copy icon that confirms the copy. The dialog, the account actions, the clone and delete dialogs and the profile picker are now available in German.
