### Changed: The unattended role-password step now refuses empty input and checks the result

The unattended `\password` example in `deploy/linux/README.txt` and in the header of
`sql/bootstrap/00_create_role_and_database.sql` piped the password into psql without a guard. When
standard input is empty or runs out (an unset or empty shell variable, or fewer lines than
`\password` commands), the server answers "empty string is not a valid password, clearing password"
and psql exits 0, even with `ON_ERROR_STOP`. The role is left without a password, the step reports
success and the installation fails later, when the server cannot connect ([GH#450]). The example now
stops on an unset or empty variable (`: "${OWNER_PW:?}"`) and checks afterwards that the role has a
SCRAM-SHA-256 verifier (superuser administrator) or can log in (any other administrator). With several
roles, supply one password and one confirmation line per `\password` command. The password still
appears neither on a command line, in a psql variable nor in the server log. CI runs the documented
sequence with an empty and an unset variable and expects it to fail.

**Action on upgrade:** none for the product. If you copied the earlier example into configuration
management, add the guard and the check.

[GH#450]: https://github.com/Shadoukita/ShadouCMDB/issues/450
