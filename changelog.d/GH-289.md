### Fixed: NUL characters in request values return 400 instead of 500

A text value containing U+0000 (for example `"abc\u0000def"` in a CI attribute) passed validation and
then failed in PostgreSQL, which cannot store it: the API answered `500 INTERNAL_ERROR` and logged an
unhandled database error ([GH#289]). The API now refuses such a value in any request body or query
string with `400 VALIDATION_ERROR`, detail code `invalid_character` and the field concerned, before
anything is written. This covers the CI API, search and the configuration import alike. Scripts that
sent such values received a 500 before, so no stored data changes.

[GH#289]: https://github.com/Shadoukita/ShadouCMDB/issues/289
