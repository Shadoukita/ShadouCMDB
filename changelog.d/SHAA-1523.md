### Security: users can no longer take over a Person by entering its e-mail; e-mails are unique regardless of Unicode form

- **Entering your own e-mail never adopts an existing Person (GH#530).** An account without an
  e-mail address enters one after signing in (`PUT /api/v1/auth/email`). If a Person without an
  account already has that address, the request is now refused with 409 `CONFLICT`, detail code
  `person_email_taken`. Deleted Persons count too. Before, the account was linked to that Person,
  so a user could take over someone else's Person CI by typing their address. The user asks an
  administrator, who sets the address on the account under Administration > Users
  (`PATCH /api/v1/admin/users/{id}`). That still links the account to the existing Person. When no
  Person has the address, a new one is created for the user as before.
- **Look-alike addresses are one address (GH#531).** E-mail addresses are compared ignoring case
  and Unicode form: composed and decomposed characters (`é` and `e` + combining accent) and
  compatibility forms such as full-width letters (`ａｌｉｃｅ@example.test`) now match their plain
  form. This applies to account e-mails, the Person's Email and the addresses that OpenID Connect
  and LDAP providers send. New addresses are stored in Unicode NFKC, so full-width letters are
  saved as ASCII. Stored addresses keep their form.

**Upgrade:** take a backup, then run `shadoucmdb migrate`.

- Migration 0045 adds the function `cmdb.email_key` (NFKC, then lower case) and rebuilds the
  unique indexes `users_email_uq` and the Person Email index on it.
- If several accounts, or several Persons, have addresses that differ only in Unicode form, the
  migration stops and lists them (accounts by username, Persons by CI ident). Nothing is changed.
  Give each its own address with the previous release, then run `migrate` again.
- On PostgreSQL 17 and later, lower case follows Unicode whatever the database's locale (the
  built-in `pg_c_utf8` collation). On PostgreSQL 13 to 16 it follows the database's `LC_CTYPE`, as
  before; a database created with the `C` locale only lowers ASCII letters. A database whose
  server encoding is not UTF8 compares lower case only, as before.
- After a PostgreSQL major-version upgrade, run `REINDEX INDEX cmdb.users_email_uq` and reindex the
  Person Email index (`uq_…` in the People area's schema), as for any expression index on text,
  when the PostgreSQL release notes report a Unicode update.
