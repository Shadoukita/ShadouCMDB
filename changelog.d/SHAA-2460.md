### Added: Mark fields that identify one CI, so a clone leaves them empty

Attribute definitions have a new setting, `isIdentifying`: the field holds a value that belongs to
one CI only, such as a serial number, asset tag or MAC address. When an operator clones a CI, the
web UI leaves identifying fields empty on the copy instead of copying the original's value. The
setting is a hint for clients; the server does not enforce uniqueness of these values.

- `POST /api/v1/attribute-definitions` and `PATCH /api/v1/attribute-definitions/{id}` accept
  `isIdentifying` (default false). Attribute definitions and the effective attributes of a class
  return it, and `GET /api/v1/attribute-definitions?isIdentifying=true` lists the marked fields.
- Changes to it are recorded in the audit log like any other change to a field.
- Configuration files now carry it (format version 12). When you import an older file, existing
  fields keep their setting and new fields are not identifying.
- The IT infrastructure template marks Serial number and Asset tag as identifying on new installs.
  On an existing installation, mark them yourself under Data model if you want the same behaviour.

**Upgrade:** migration `0069` adds `is_identifying` to `ci_attribute_definitions`, set to false
for every existing field. Run `shadoucmdb migrate` before starting the new release.
