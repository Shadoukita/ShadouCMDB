### Security: authenticator secrets are encrypted with a key kept outside the database

Until now the database stored every user's authenticator (TOTP) secret as it is, so anyone who
could read the database, a `pg_dump` or a `shadoucmdb backup` file could compute every user's
sign-in codes and get past two-factor sign-in ([GH#189]). The server now encrypts these secrets
with AES-256-GCM under a key read from the file named by the new `ENCRYPTION_KEY_FILE` setting,
bound to each user, so a secret copied onto another account does not decrypt. The key never
enters the database, the logs or a backup. Backups record which key their secrets are encrypted
with, and `restore` warns when the configured key does not match. A key can be rotated with
`ENCRYPTION_KEY_PREVIOUS_FILE`. New commands: `shadoucmdb generate-encryption-key` creates a
key, and `shadoucmdb mfa reset-undecryptable` turns off two-factor sign-in (audited, `reason:
key_lost`) for users whose secret is under a lost key. A secret that does not decrypt fails
closed and is audited as `mfa.failure` with `reason: secret_undecryptable`. The OIDC client
secret and the directory bind password are still stored unencrypted ([GH#199]).

**Action on upgrade (required):** `shadoucmdb serve` no longer starts without
`ENCRYPTION_KEY_FILE`. Before restarting the server on the new release, create a key with
`shadoucmdb generate-encryption-key --out <path>`, make it readable only by the service account,
set `ENCRYPTION_KEY_FILE=<path>` in the env file, and store a copy apart from the database
backups (for example in your password vault). `shadoucmdb migrate` warns when the setting is
missing. At its first start the server encrypts the existing secrets (migration 0025 adds
`user_totp.key_id`); nobody has to set up two-factor sign-in again. Keep the key as long as you
keep backups taken after the upgrade: without it, their two-factor enrolments cannot be used.
Going back to an earlier release after the upgrade needs a restore of a backup taken before it.
See `docs/security/hardening.md` ("Encryption key").
