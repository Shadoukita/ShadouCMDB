### Fixed: busy refusals and body timeouts name the caller in the log

A request refused with `503 SERVER_BUSY` by the fair-share limits, or answered `408 REQUEST_TIMEOUT`
because its body did not arrive in time, was logged with only its method, path and request id. These
requests never reach a handler, so the audit log has nothing on them either, and an operator could
not tell which account or network caused a burst of refusals ([GH#571]).

The `request` span of the JSON log now carries the caller once it is known, so both the
`request refused: …` warning and the `request completed` line name it:

- `user_id` for every authorised request, and `token_id` when it used an API token.
- `net` and `wide` (the client's IPv4 /24 or IPv6 /64, and its IPv4 /16 or IPv6 /48) when a sign-in,
  setup or other public request is refused for the public body budget or its body times out. Only
  the networks are logged, never the client's address, and nothing when
  `AUDIT_CAPTURE_CLIENT_IP=false`.

**Upgrade note:** no action needed. Log pipelines that parse the `span` object see the new fields.
