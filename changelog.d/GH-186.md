### Security: the configuration export only contains permission profiles for callers who may read them

`GET /api/v1/admin/config/export` needed only `config.export_import`, but its file always held every
permission profile (names, global permissions, per-class grants and whether MFA is required), which
the same caller was refused on `GET /api/v1/admin/profiles` ([GH#186]). The `permissionProfiles`
section is now only included when the caller also holds `profiles.manage` or `users.manage`, the
permissions that read profiles on their own admin API. For other callers the key is left out of the
file; everything else in the export is unchanged.

**Upgrade:** if you use the export as a configuration backup or to compare installs, run it as a user
or API token with `profiles.manage` or `users.manage` in addition to `config.export_import`, or the
file no longer contains the profiles. Importing a file without the section leaves the target's
profiles untouched, as before. No schema change.
