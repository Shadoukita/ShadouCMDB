### Added: Subtitle field per CI type, relationship-type categories, and a CI's last change

Three additions for the redesigned inventory and CI pages:

- **Subtitle field per CI type.** A CI type can name one of its fields, or a field it inherits, as
  its subtitle (`subtitleAttributeId` on `/api/v1/ci-classes`). The redesigned inventory shows that
  field's value under a CI's name, for example a server's model. Types without a subtitle field
  show the type name instead. If a type moves under a parent that does not provide the field, the
  setting is cleared. Changes are audited like other type edits.
- **Relationship-type categories.** A relationship type can have an optional `category`, a free-text
  group heading of up to 100 characters such as `Location` or `Network & power`. The CI page groups
  relationships by category. Administrators with permission to edit relationship types set it. The
  category is audited and is included in relationships, the relationship graph, and configuration
  export/import. The configuration format version is now 13, and files of earlier versions still
  import. The migration fills in a category for the starter template's `located_in` and
  `connected_to` types only when their labels are still the template's own.
- **A CI's last change.** `GET /api/v1/configuration-items/{id}` returns `lastChange`: the time,
  action and actor of the CI's newest create, update, delete or restore audit entry. The UI can
  show "Updated … by …" without reading the audit history. The database derives this value from the
  audit log, so the two always match. The actor is `null` for callers without `audit.view`. Exports
  and workflow events do not count as changes.

**Upgrade:** migration `0070_redesign_metadata` runs on start. It adds two nullable columns and the
`cmdb.ci_last_changes` table, and fills that table from the audit entries still in the log. CIs
whose entries audit retention has already removed have `lastChange: null` until their next change.
No configuration is needed.
