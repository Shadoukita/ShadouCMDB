### Fixed: The DAST gate no longer counts refused requests as reaching their handlers

The release pipeline's DAST job checks in the server log that ZAP's requests with real object ids
reached the handlers they test. It counted every status other than `400`, so a session scan that had
lost its cookie or CSRF token (`401`/`403`), or a server failing with `5xx`, still passed and
reported coverage the scan never had ([GH#345]). Each checked operation now counts only the
statuses its handler returns (for example `200`/`404`, or `204`/`404`/`409` for deleting a user).
The job summary lists the other statuses seen.

No action is needed when upgrading. This change affects only the project's release evidence, not
the server.
