### Added: Notes on configuration items

A configuration item now carries a stream of notes: short, signed, timestamped texts such as
"Disk replaced in slot 4", kept apart from the CI's attributes and versions. This is the API for the
Notes tab of the CI detail page.

- `GET /api/v1/configuration-items/{id}/notes` lists the notes of a CI, newest first and paginated,
  to anyone who may read the CI. A soft-deleted CI keeps its notes and they stay readable.
- `POST …/notes` adds a note (plain text, at most 10,000 characters). This needs edit permission
  on the CI's class and a CI that is not deleted.
- `PATCH` and `DELETE …/notes/{noteId}` change or remove a note. Only its author may do this,
  within the edit window, and the request must send the `version` it loaded. An administrator
  may delete any note at any time.
- `GET` / `PUT /api/v1/ci-note-settings` holds the note policy. `editWindowMinutes` defaults to
  24 hours (`0`: never, `null`: no limit). `retentionDays` is off by default; when set (30 to
  36,500), the server deletes older notes within the hour and every hour after that. Only an
  administrator may change the policy.

Every write is audited under the new entity types `ci_notes` and `ci_note_settings`. Updates and
user deletes record the text before and after. Deletes made by the retention sweep are recorded
by the system actor `note retention` and leave the text out. An audit reader sees a note's entries
only if they may read its CI. Notes and the policy are included in backups and restored with them.

**Upgrade:** migration `0070` adds the tables `ci_notes` and `ci_note_settings` and grants the API
role access to them. It does not rewrite any existing data. Run `shadoucmdb migrate` before you
start the new release.
