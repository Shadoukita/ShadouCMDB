### Security: a template install no longer tells whether a hidden type holds CIs

Installing a starter template (`POST /api/v1/admin/templates/{key}/install`) adds the template's required fields
to an existing type of the same key. The returned schema change then said either that the field "becomes
required" or that it "stays nullable: some assets have no value", so a user with the data-model permission learned
whether a type they may not view held any CI ([GH#276]). An administrator's reconcile had the same tell.

For a user who may not view the type and every type below it, such a field now stays nullable without any CI being
read, and the note is the same whether or not there are CIs. A later reconcile by a user who may view them all
(or `migrate`) makes it required once every CI has a value. Types created by the same install are not affected.

[GH#276]: https://github.com/Shadoukita/ShadouCMDB/issues/276
