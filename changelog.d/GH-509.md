### Security: the audit export no longer carries usernames that match no account

A sign-in refused for a name that matches no account is often a password typed into the username
field. Since [GH#415] the server log leaves such names out, but `AUDIT_EXPORT` still sent the
`login.failure` and `login.locked` rows with `attemptedUsername` as typed — and with
`AUDIT_EXPORT=stdout` they land in the same journal or container log ([GH#509]). Exported rows now
carry `"attemptedUsername": null` and `"attemptedUsernameRedacted": true` when the name matches no
account (compared case-insensitively, as sign-in does); names of existing accounts are exported as
before. The audit log in the database is unchanged and still holds the name for users with
`audit.view`, and `rowHash` still matches the stored row, so `shadoucmdb audit-verify` comparisons
are unaffected.

**Upgrade:** no configuration, API or schema change. SIEM rules that key on `attemptedUsername` of
unknown names should use the client address (`ipAddress`) or `requestId` instead.
