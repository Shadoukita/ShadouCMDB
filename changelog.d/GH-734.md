### Security: refused CI writes no longer name workflows the user may not view

When a CI write sets a state field that an active workflow drives, it is refused with
`WORKFLOW_CONTROLLED_FIELD` (409). The field error named the driving workflow even when the user may
not view every CI type that workflow covers, so it answers "not found" to them. This affected
creating and editing CIs, bulk edits and import rows. Only the workflow key was disclosed, no CI data.
([GH#734])

The status, error code and field code (`workflow_controlled`) are unchanged. When the workflow is
hidden from the user, the message now says "another active workflow on these CIs" instead of its key,
using the same rule as the workflow conflict messages ([GH#718]). A user who may view the workflow
still sees its name.
