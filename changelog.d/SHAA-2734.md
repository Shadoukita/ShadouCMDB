### Added: e-mail notifications for workflow actions

Workflow actions can now send e-mail when a transition runs, an approval is requested, reaches a step, is
closed or is overdue, and when a workflow is cancelled or forced. E-mail is **off by default**: the operator
sets `MAIL=smtp`, the relay (`SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_TLS_CA_FILE`, `SMTP_USERNAME`,
`SMTP_PASSWORD_FILE`, `SMTP_TIMEOUT_SECS`), the sender (`MAIL_FROM`, `MAIL_REPLY_TO`) and `PUBLIC_URL`; see
`.env.example`. The server refuses to start with `MAIL=smtp` and a missing relay, sender or `PUBLIC_URL`, with
`SMTP_SECURITY=none` unless `SMTP_ALLOW_PLAINTEXT=true`, and with SMTP authentication over an unencrypted
connection. The password is read from a file only.

- **Recipients.** The owner of the CI, the users or groups named in a reference field of the CI, the
  technical or business owners of the business services the CI belongs to, the workflow's participants
  (the user who ran the event, who started the workflow, who requested the approval, the current step's
  approvers and their delegates), users, groups and permission profiles. Fixed addresses are possible only
  when the operator sets `MAIL_ALLOW_EXTERNAL_ADDRESSES=true` and `MAIL_ALLOWED_DOMAINS`, and they only get a
  notice with no CI details.
- **Only what the reader may see.** Each message is rendered for one recipient. A recipient who may not
  view the CI's class gets nothing, and a reference to a CI they may not view reads "a CI you cannot view".
  The check is repeated when a message is sent, so a retry hours later does not leak a CI whose rights
  were withdrawn in between.
- **Language.** English or German, by the user's chosen language (stored when they change it in the web
  UI), else `MAIL_DEFAULT_LOCALE`. Each message has a plain-text and an HTML part with inline styles only,
  one link to the web UI built from `PUBLIC_URL`, and a footer that says why the reader got it. There are no
  approve or reject links. The copy conventions are in `backend/src/modules/mail/templates/README.md`.
- **Volume.** One bulk transition sends each recipient one message that lists the CIs (the first 50 by
  name). Past `MAIL_MAX_PER_RECIPIENT_PER_HOUR` messages (default 30) to one recipient in an hour, the rest
  are collected into one digest at the end of the hour. Past 5 approval requests by one requester on one CI
  in an hour, the rest go to the digests too.
- **Delivery.** Messages are sent from the workflow action outbox. A temporary refusal by the relay (4xx)
  is retried; a permanent one (5xx) marks the delivery dead for that recipient only. Each delivery keeps
  one `Message-ID` across retries. Messages carry `Auto-Submitted: auto-generated` and
  `X-Auto-Response-Suppress: All`, and no value can add a header to a message. The relay's error text is
  stored with every e-mail address masked (`c***@corp.example`), so neither a delivery's detail nor the mail
  status shows a fixed address in clear.
- New endpoints `GET /api/v1/admin/mail/status` (the settings, without credentials, and the last outcomes)
  and `POST /api/v1/admin/mail/test` (a test message to the caller's own address, audited as `mail.test`).
  Both need `workflows.manage` or `webhooks.manage`.

Upgrade: migration `0079` adds two indexes to the workflow action tables. Nothing changes until the
operator sets `MAIL=smtp`.
