### Security: business service membership changes only through the business service

Business service members are meant to change only on the business service
(`/business-services/{id}/members`), which enforces `BUSINESS_SERVICE_MAX_MEMBERS`,
`BUSINESS_SERVICE_MAX_NESTING` and records the membership change in the audit log. Two other paths
reached membership ([GH#410]):

- **Relationship rules and imports.** A data model manager could add a relationship rule on the
  built-in membership type, and a bulk import mapped to that type then wrote member edges directly:
  without the member limit, with nesting checked only against the hard ceiling of 8, and without the
  membership audit entry. The membership type now takes no rules (`POST`/`PATCH
  /relationship-rules` return `400` with code `system_relationship_type` on `relationshipTypeId`,
  and the database refuses it too). An import mapping naming the type is refused with the same code
  on the column's `target.typeKey`, and mapping suggestions no longer offer it. A configuration
  transfer file carrying such a rule imports without it.
- **Moving a member into the business service type.** A CI that became a business service while
  services included it nested them one level deeper without any check. The API has refused that
  move since [GH#409]; the database now refuses it too (`400` with `business_service_class` on
  `classId`).
- `GET /configuration-items/{id}/business-services` now sets `truncated` when services including
  the CI are nested deeper than `BUSINESS_SERVICE_MAX_NESTING`; the deeper ones are left out, as
  before.

**Upgrade:** migration 0041 deletes every relationship rule on the membership type. Those rules
never changed what the database accepted for membership (any CI may be a member), so nothing that
worked through the business service stops working. Saved import mappings that used the type fail
validation and need that column removed. Service chains already deeper than the limit are left as
they are; adding further levels to them is refused.

[GH#410]: https://github.com/Shadoukita/ShadouCMDB/issues/410
