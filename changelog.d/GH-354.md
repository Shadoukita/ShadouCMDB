### Changed: the Application field "Criticality" is replaced by the core Criticality field

Applications no longer show two *Criticality* values. The IT infrastructure starter template's
Application field `criticality` duplicated the core **Criticality** that every CI has since impact
analysis. The template no longer creates the field, the demo data sets the core field instead, and
installs that already have the field are migrated:

- Migration 0036 copies each Application's value (subclasses included) onto the core field when the
  core field is empty and the value matches a value of the *Criticality* list by key or name
  (`low`, `medium`, `high`, `critical` all match the default list). Each copy is recorded in the CI's
  history (actor `migration 0036`). A core value that was already set, or that a user sets while the
  migration runs, is kept (GH#391).
- The field is then **archived**, not deleted: its column and every value stay readable, forms hide
  it, and it takes no new values. A field `criticality` on any other class, or of another type
  (number, date, …), is left alone.
- The CI detail page lists the values of archived fields in their own **Archived fields** panel,
  labelled *(archived)*, instead of next to the active fields or under *Not defined by this class*
  (GH#369). This applies to every archived field, not only this one.
- A configuration export from before this change still carries the field. Importing it creates or
  keeps the field archived, and the import result names it in `warnings`. If you restored the field
  on the target install, the import leaves it active.

**Upgrade:** take a backup, then upgrade as usual; migration 0036 runs on start and needs no
downtime. Afterwards, check the field's audit entry (*Audit log*, entity type
`ci_attribute_definitions`, actor `migration 0036`): it counts the CIs whose core field was set
(`criticalitySet`), already held that value (`alreadySet`) or kept a different core value
(`keptCoreValue`), and lists the values that matched no Criticality value (`notMappedValues`).
Set the core Criticality on those CIs by hand; their old value is still shown in the archived
field. Saved bulk-import mappings and inventory views that use `attributes.criticality` on
Applications should be switched to the core field. To bring the old field back, restore it
(`PATCH /api/v1/attribute-definitions/{id}` with `{"isActive": true}`); nothing was lost.
