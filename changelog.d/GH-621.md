### Fixed: Detail page windows no longer cut their inline inputs in half

A layout section placed from the grid (a layout saved before free placement, one converted by an
upgrade, or one saved through the API without frames) got a window height of 48 px per row of fields.
Since the detail page edits fields in place, a row of fields (label, input and hint) needs about 80 px,
so those windows showed their inputs cut in half behind an inner scrollbar, and the "Record" window
cut off its second row ([GH#621]). Windows placed from the grid are now 88 px for the title bar and
padding, 82 px per row of fields, 28 px per separator, and 252 px for the record details.

The UI settings document's `layoutFormat` is now 4. A document of an older format (an older
configuration export, an older settings version being restored) is converted on save the same way
as the stored layouts below.

**Upgrade:** migration 0058 resizes every tab whose windows are all still where the old estimate put
them, in the layout templates, the class layouts and the CIs' own layouts: same columns and order,
taller rows. A tab with any window moved or resized in the layout editor is left exactly as it is.
Only window frames change; sections, fields, separators, notes and hidden and read-only fields are
kept. The converted settings are saved as a new settings version, and every change is audited with
actor `migration 0058`. No action needed.
