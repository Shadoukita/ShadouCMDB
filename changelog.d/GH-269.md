### Security: resending a hidden reference no longer tells whether its CI was deleted

A CI's reference into a class the caller may not view is shown as hidden, without its name or
deletion state. Saving the CI with that reference unchanged was accepted only while the referenced
CI was live, so a user who could edit the CI learned whether the hidden CI had been deleted; with a
`classId` change they could also learn whether it belonged to a given class ([GH#269]). Resending
the value a reference attribute already holds is now no change and is accepted without checks,
whether the referenced CI is live, deleted or hidden. This also means a form that saves every field
no longer fails because a referenced CI was deleted in the meantime. After a `classId` change, an
attribute of the new class that only shares the key is a new reference and is checked as one.

**Upgrade:** nothing to do.
