### Security: Revoking an API token you may not see answers 404, not 403

`DELETE /api/v1/admin/api-tokens/{id}` answered `403 FORBIDDEN` for a token whose owner holds
permissions the caller does not, and `404 NOT_FOUND` for an unknown id. A user manager who knew a
token id could therefore tell that the token exists, although the token list and
`GET /api/v1/admin/api-tokens/{id}` hide it ([GH#458]). It now answers `404 NOT_FOUND` with the
same body as for an unknown id, also when the token is already revoked. Nothing was revoked or
disclosed before; administrators, and callers who cover the owner, revoke as before, and your own
tokens stay revocable.

**Upgrade:** scripts that told the two cases apart by `403` on this route now see `404`.
