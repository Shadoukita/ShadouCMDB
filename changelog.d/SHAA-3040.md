### Added: Lifecycle template for new workflows (planned → active → retired)

**Administration › Workflows › New workflow** now asks what the workflow starts from: a **Blank
workflow**, designed from scratch as before, or the **Lifecycle (planned → active → retired)**
template; **New lifecycle workflow** on the list opens the form with the template chosen. The
template creates the states Planned (initial), Active and Retired (final) and the transitions
Put into service (Planned → Active), Retire (Active → Retired) and Cancel plan (Planned → Retired)
as the new workflow's draft. With a state field, each state is matched to an active value of the
field's list by key or name (`planned`; `active` or `in_service`; `retired` or `decommissioned`),
and a state without a match is shown so the value can be picked in the designer. Tick the
permission profiles that may run the transitions in the same step; without one, only
administrators can run them and the check says so. The result is an ordinary draft: change it in
the designer, publish it, and export and import it like any other workflow. If a step fails after
the workflow was created, the workflow is deleted again, so no half-built workflow is left. Only
CI types the manager may view and edit, with their subtypes when those run the workflow too, can
be chosen.
