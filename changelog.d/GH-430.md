### Security: attribute validation patterns stay within a fixed memory budget on many-core hosts

Attribute validation: the regex cache memory budget now includes per-thread matching caches, so
worst-case memory stays bounded on many-core hosts ([GH#430]). Previously the 64 MiB budget counted
only the compiled patterns. The regular-expression library also kept a matching cache per pattern
for every thread that used it, so concurrent writes or imports against many stored patterns could
hold about 0.8 GiB on a 16-thread host.

Each pattern now keeps at most 4 idle matching caches, and all patterns together keep at most
32 MiB of them. Compiled patterns are counted at their measured size instead of a 64 KiB or 1 MiB
tier, and the least recently used patterns are evicted first instead of clearing the whole cache.
The worst case for validation patterns is now about 96 MiB, plus about 1 MiB for each thread that
is validating a value at that moment, independent of the number of patterns. Data models with many
ordinary patterns, such as e-mail or ID formats, are no longer recompiled on every check.

[GH#430]: https://github.com/Shadoukita/ShadouCMDB/issues/430
