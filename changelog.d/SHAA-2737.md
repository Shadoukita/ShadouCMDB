### Added: web UI for webhooks, workflow deliveries and outbound e-mail

The outbound channels of workflow actions can now be run from the web UI.

- **Administration › Webhooks** (`webhooks.manage`). Lists, creates, edits and deletes endpoints. The
  signing secret is shown once, with a copy button, and cannot be read again after the dialog closes. A
  rotated secret is shown the same way, and the old secret can stay valid for a grace period. Ping
  explains a refusal in plain words, for example that the host resolves to a private network address. Endpoints can be paused and resumed, and the host
  allowlist is edited on the same page. A user with `workflows.manage` only sees the endpoints' key, name
  and status, and cannot create or change one.
- **Workflow deliveries.** Each workflow has a deliveries page with status, action, kind and date filters.
  The filters are kept in the URL. The page shows each delivery's detail (attempts, last error, run status)
  and can retry or discard the selected deliveries or every dead one. A banner shows when the outbox is
  overloaded, when dead deliveries exist, when runs were suppressed, or when the delivery workers stopped
  reporting. The workflow's Actions tab links to it.
- **Administration › Outbound e-mail.** Shows the mail settings and recent outcomes, and sends a test
  message to the administrator's own address.
- **Account.** Users choose the language of their notification e-mails (English or German), or follow the
  server default.

Upgrade: nothing to do. The pages show that webhooks or e-mail are off until the operator turns them on.
