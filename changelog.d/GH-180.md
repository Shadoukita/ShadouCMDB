### Security: refused field changes no longer show stored values of CI types the user cannot view

When a field change would invalidate stored data (a text field becoming an enum whose list leaves out
stored values, or a type change such as text to integer or date that some values cannot survive), the
refusal quoted up to five of the offending stored values, including those of deleted assets. A user
with the data-model permission but no view right on a CI type could use the change preview, which
changes nothing and writes no audit entry, to read that type's attribute values ([GH#180]). A refusal
now quotes stored values only when the user may view the field's type and every type below it, whose
assets store the field too. Every other user is told how many values stand in the way, not which. The
change is still refused either way.

**Upgrade:** nothing to do. No API or schema change. Data-model managers without view rights on a
type now need a user who can view it to find the values to correct.

[GH#180]: https://github.com/Shadoukita/ShadouCMDB/issues/180
